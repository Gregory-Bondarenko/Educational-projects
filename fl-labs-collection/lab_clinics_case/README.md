# Консорциум клиник: запускать ли FL

Самостоятельная работа №1 по дисциплине «Федеративное машинное обучение», письменная, без кода

## Задача

Шесть частных клиник из разных регионов хотят вместе улучшить модель риска послеоперационных осложнений. Сырые данные друг другу не отдают, объёмы, протоколы и ИТ-команды у всех разные. Нужно объяснить, почему не подходит централизация, определить тип сценария, назвать преимущества и риски FL и дать рекомендацию

## Решение

**Почему не централизация.** Данные о здоровье относятся к специальной категории персональных данных (ст. 10 152-ФЗ) и к врачебной тайне (ст. 13 323-ФЗ). Для передачи другой клинике нужно согласие каждого пациента, а для архивных записей его не собрать. Кроме того, клиники конкурируют, и общий массив даёт его владельцу преимущество, которого остальные не хотят. Наконец, единое хранилище медицинских данных шести организаций само становится мишенью

**Тип сценария.** Cross-silo: участников шесть, все организации со своей инфраструктурой и стабильной связью, каждая хранит тысячи записей и участвует почти в каждом раунде

**Преимущества:**
- сырые записи не покидают клинику, по сети ходят только параметры модели
- осложнения редки, и общая модель видит больше редких случаев, чем модель любой одной клиники
- разные регионы и протоколы делают модель устойчивее к смене условий
- каждый участник сохраняет контроль над данными и может выйти из консорциума
- поверх общей модели клиника может дообучить свою версию

**Риски и ограничения:**
- неоднородность данных замедляет и смещает FedAvg, могут понадобиться SCAFFOLD или персонализация
- разная кодировка диагнозов и процедур: без общей схемы данных модель учится на несопоставимых признаках, и это может оказаться самой дорогой частью проекта
- утечка через обновления: в работе по приватности простая атака по членству угадывала в 70% случаев
- крупная клиника доминирует в среднем, а одно испорченное обновление может сломать модель для всех
- самый слабый по ИТ участник задаёт темп и создаёт уязвимости
- статус параметров модели как персональных данных в российском праве прямо не определён
- если модель влияет на клинические решения, её могут потребовать зарегистрировать как медицинское изделие

## Результат

Запускать сразу в продуктовом формате не стоит. Разумнее пилот на 3–6 месяцев, если выполнены условия: подписано соглашение консорциума о правах на модель и ответственности, согласована общая схема признаков, агрегация защищённая и стоит у независимой стороны, а модель только подсказывает врачу, но не решает. Критерий успеха: общая модель лучше локальной модели каждой клиники на её же отложенных данных. Если выигрывают только мелкие клиники, крупным нужна отдельная мотивация, например персонализированные модели
