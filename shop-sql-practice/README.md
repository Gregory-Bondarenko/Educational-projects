# Практическая работа: анализ данных интернет-магазина (PostgreSQL)

## Условие

Дан исторический датасет интернет-магазина за 2023-2024 год: клиенты,
товарный каталог, заказы, состав заказов и события пользователей на сайте
(заход на сайт, просмотр товара, добавление в корзину, оформление,
покупка). Нужно спроектировать под эти данные схему БД и с помощью SQL
ответить на вопросы ниже.

## Вопросы / задания

**JOIN**
1. Список заказов вместе с именем клиента и статусом.
2. Клиенты, которые ни разу не сделали заказ.
3. Товары, которые ни разу не заказывали.
4. Полное сопоставление клиентов и заказов (в т.ч. "лишние" строки с обеих сторон).
5. То же самое, но в одном запросе с оконной функцией: ранжирование клиентов по сумме покупок внутри своей страны.

**Агрегация**
6. Выручка по месяцам.
7. Топ-10 товаров по выручке.
8. Средний чек по странам.

**Оконные функции**
9. Накопительная выручка по дням (running total).
10. Ранжирование клиентов по сумме покупок (RANK / DENSE_RANK).
11. Скользящее среднее выручки за 7 дней.

**CTE и подзапросы**
12. Когортный анализ: retention клиентов по месяцу регистрации.
13. RFM-сегментация клиентов (Recency, Frequency, Monetary).

**Продвинутые темы**
14. Воронка продаж: сколько сессий доходит до каждого шага и конверсия между шагами.
15. Реферальная сеть клиентов (recursive CTE): размер сети приглашений у каждого клиента.
16. Представление (VIEW) с помесячной сводкой по магазину.

## Структура таблиц

- `customers`: клиенты (страна, дата регистрации, кто пригласил)
- `products`: товары
- `orders` / `order_items`: заказы и их состав
- `events`: действия пользователей на сайте (для воронки)

## Как запустить

```bash
createdb shop_practice
psql -d shop_practice -f 01_schema.sql
psql -d shop_practice -f 02_data.sql
psql -d shop_practice -f 03_joins.sql
psql -d shop_practice -f 04_aggregation.sql
psql -d shop_practice -f 05_window_functions.sql
psql -d shop_practice -f 06_cohort_rfm.sql
psql -d shop_practice -f 07_funnel_referral.sql
psql -d shop_practice -f 08_view.sql
```

Нужен PostgreSQL 13+ (используются `FILTER`, `NTILE`, `RANK`/`DENSE_RANK`,
recursive CTE).

## Что получилось / выводы по заданиям

- **JOIN (1-5).** LEFT/RIGHT/FULL JOIN пригодились не для "красоты", а чтобы
  находить клиентов без заказов и товары без продаж, и именно это на практике
  и есть основная причина использовать не-INNER джойны.
- **Агрегация (6-8).** Показывает динамику выручки и то, какие товары и
  страны дают основной доход.
- **Оконные функции (9-11).** Running total и moving average: то, что
  обычным `GROUP BY` не посчитать, нужен именно `OVER()`.
- **Когорты и RFM (12-13).** Отвечают на вопрос "какие клиенты уходят" и
  "кто приносит больше всего денег", это типичная задача продуктовой аналитики.
- **Воронка и реферальная сеть (14-15).** Воронка показывает, на каком шаге
  теряется больше всего пользователей. Рекурсивный CTE здесь единственный способ
  посчитать сеть приглашений произвольной глубины без циклов в коде.
- **VIEW (16).** Вместо того чтобы копировать один и тот же запрос сводки
  каждый раз, вынесли его в представление.
