# VK Engagement Prediction

Индивидуальный цифровой проект (2 курс, направление «Прикладная информатика», профиль «Анализ данных»).

Тема: прогнозирование вовлечённости (просмотров и лайков) постов в спортивном сообществе ВКонтакте на основе текста и времени публикации.

## Зачем

Я администрирую спортивное сообщество в VK, и мне регулярно приходится объяснять, почему один пост «выстрелил», а другой — нет. Проект — попытка автоматизировать этот разбор: собрать историю постов через VK API, найти, какие признаки (время, длина текста, эмодзи, тематика) связаны с просмотрами и лайками, и обучить модель, которая по параметрам будущего поста даёт прогноз ещё до публикации.

## Результат

- Датасет: ~9000 постов сообщества за 12+ месяцев, собранные через `wall.get`.
- Модель: `RandomForestRegressor` (scikit-learn) — по одной модели на просмотры и на лайки.
- Признаки: час и день недели публикации, длина текста, число эмодзи, категория поста (определяется словарём ключевых слов — «Матч / Результаты», «Праздники / Поздравления» и т.д.).
- Качество: R² ≈ 0.55 для обеих целевых переменных. Это не отличный результат — модель объясняет чуть больше половины разброса, — но на 5–6 простых признаках без учёта текста семантически это ожидаемо. Подробности и разбор ошибок — в `docs/report.docx`.
- Практический выход — консольное приложение: вводишь текст поста, день недели и час, получаешь прогноз просмотров и лайков.

## Структура репозитория

```
vk-engagement-prediction/
├── main_pipeline/          # рабочий, воспроизводимый пайплайн
│   ├── 01_collect_data.ipynb   # сбор постов через VK API
│   ├── 02_clean_data.ipynb     # чистка выбросов (IQR)
│   ├── 03_train_model.ipynb    # категоризация, признаки, обучение RandomForest
│   ├── 04_cli_predict.ipynb    # консольное приложение для прогноза
│   └── models/                 # обученные модели (.pkl)
├── experiments/             # побочные исследования на том же датасете, в продукт не вошли
│   ├── eda_correlations.ipynb
│   ├── clustering_and_sentiment.ipynb
│   ├── classification_attempt.ipynb
│   └── bi_export.ipynb
├── data/                    # датасеты на разных этапах обработки
├── docs/                    # отчёт, презентация, список литературы
├── requirements.txt
└── .env.example
```

Порядок запуска пайплайна — по номерам в `main_pipeline/`: каждый следующий ноутбук читает файл, который сохранил предыдущий.

## Как запустить

```bash
git clone <repo_url>
cd vk-engagement-prediction
pip install -r requirements.txt
cp .env.example .env   # и вписать туда свой VK_API_TOKEN
```

Дальше по порядку: `01_collect_data.ipynb` → `02_clean_data.ipynb` → `03_train_model.ipynb` → `04_cli_predict.ipynb`.

Если своего сообщества VK для сбора данных нет — можно начать сразу со второго шага: в `data/vk_posts_clean.xlsx` уже лежит очищенный датасет из моего сообщества, а в `main_pipeline/models/` — уже обученные модели, так что `04_cli_predict.ipynb` можно запускать сразу, без повторного обучения.

## Эксперименты — и почему они отдельно

В процессе работы над проектом я пробовал несколько подходов, которые не стали частью финального пайплайна. Выкидывать их не стал — они показывают ход мысли и то, что не всякая гипотеза окупается:

- **`eda_correlations.ipynb`** — разведочный анализ: корреляции между просмотрами/лайками/комментариями, зависимость просмотров от часа и дня недели.
- **`clustering_and_sentiment.ipynb`** — отдельное задание по теме семестра (методы корреляции и кластеризации): K-Means по постам с добавлением тональности текста (TextBlob) и признака наличия медиа. Использует свою версию признаков, не связан с основным пайплайном.
- **`classification_attempt.ipynb`** — ранняя версия задачи как бинарной классификации («лайков больше медианы или нет») через `RandomForestClassifier`. От неё отказался в пользу регрессии — она даёт число, а не просто «выше/ниже среднего», что полезнее на практике.
- **`bi_export.ipynb`** — выгрузка датасета с посчитанными длиной текста и числом эмодзи для внешнего BI-инструмента (Power BI / Tableau). В проект не встроено, просто пригодилось для собственной визуализации.

## Ограничения

- Признаков мало (5–6), текст поста учитывается только через длину, число эмодзи и категорию по ключевым словам — реальной семантики (тематика, тон) модель не видит.
- Категоризация по словарю ключевых слов — грубая эвристика, часть постов попадает в «Другое».
- R² ≈ 0.55 означает, что почти половина вариации в реакции аудитории остаётся необъяснённой — вирусные посты и внешние факторы (алгоритм ленты VK, инфоповоды) модель не учитывает.
- Дальнейшие шаги, которые в проекте не сделаны: эмбеддинги текста вместо ключевых слов (word2vec/BERT), учёт вложений (фото/видео), временные модели вместо статичных признаков.
